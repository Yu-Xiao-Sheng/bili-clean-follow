# v2 宣传文案（Chrome 插件形态）

> FOR-69 产出，供 FOR-70（影片）与 FOR-71（发布投放）共用。口径依据：FOR-62 issue 文档 `v2-spec`。
> 投放前置条件：FOR-67 的 `docs/qa-report-v2.md` 结论为 Go。未 Go 之前任何渠道不得发。

## 0. 共用口径（所有渠道复用同一段，避免各说各话）

**它是什么**：一个 Chrome/Edge 浏览器插件。装完打开侧栏，它把你 B 站关注列表**完整读全**，用 AI 按语义分成 12 类，你按类选择保留谁、清理谁；也可以直接打字说「保留所有游戏区的，把搞笑段子和影视解说都清掉」。

**它不是什么**：不是「一键清空关注」的脚本。任何取关动作都要你先看到 diff 预览、手输 `UNFOLLOW` 才会执行，`keep` 类的 UP 主永不进候选，单次上限 50、速率 ≥800ms/条、遇风控自动熔断，事后有审计日志和「一键重新关注」补救。

**隐私口径（v2 改写，必须原文使用）**：凭据（cookie、`bili_jct`）永不出本机，也不写进日志和导出文件；昵称与简介只发给你**自己指定**的模型端点（不填 Key 就走离线规则分类，零外发）。v1 那句「数据完全不出本机」在 v2 不再成立，我们改写成上面这句，不装没事。

**CLI 说明（必须带）**：Python 命令行版已进维护模式，冻结在 v0.1.3，只做安全修复；新功能全部在插件侧。

**诚实口径（沿用 v1，别丢）**：数据缺失按「未知」处理，不按「最差」处理；列表没读全之前不给分类结论。

## 1. B 站动态（发布日首发）

标题：`给自己写了个 B 站插件：把 800 多个关注读全、分好类，然后一句话清理`

正文：
```
关注列表涨到 800 多个之后，我早就记不清自己关注过谁了。翻到第 41 页就放弃了。

所以做了个浏览器插件，跟之前那个 Python 版完全不同的用法：
1）下载 zip 解压，chrome://extensions 里「加载已解压的扩展程序」，不用装 Python、不用 clone；
2）打开侧栏点「分析我的关注列表」，它会一页一页翻到最后一页——没读全之前分类按钮是灰的，半截结果不给结论；
3）AI 把 UP 主按语义分类（游戏 / 科技 / 影视 / 知识 / 美食 / 搞笑……12 类，可以自己加类），整类保留或整类进候选；
4）也可以直接打字：「保留所有游戏区的，把搞笑段子和影视解说都清掉」，它先把影响范围算给你看（diff 预览 + 10 条样例），你确认了才算候选；
5）真要取关得手动武装：手输 UNFOLLOW、单次最多 50 条、800ms 一条、遇风控自动停，全程有审计日志，还能一键重新关注补救。

隐私说一句：cookie 绝不出本机；昵称和简介只发给你自己填的模型端点（不填就走离线规则分类）。
开源 MIT，图文安装教程在 README 顶部。【插件形态 · v2.0.0】
```

- 配图：`assets/preview-v2-promo.gif`（首图）+ 分类卡片截图 + diff 预览截图

## 2. 知乎回答（挂在「如何清理 B 站关注列表」「有哪些实用的浏览器插件」下）

结构（长答，约 900 字）：

1. **先说清痛点**：关注 800+ 的人不是不想清，是不敢清——不知道哪些是还有价值的。逐条翻到第 41 页是体力活。
2. **旧方案为什么劝退**：Python 脚本要装环境、要 F12 抓导出 JSON、要处理编码乱码。大多数人第一步就放弃。所以 v2 改成插件。
3. **安装（4 步，带截图）**：zip → 解压 → 开发者模式 → 加载已解压的扩展程序。Edge 用户走 Edge 扩展中心。
4. **关键差异（这段是知乎上的可信度来源，写实）**：
   - 必须先读全：`x/relation/followings` 一页 20 条，要翻到最后一页，中途被风控就标 `incomplete`，分类保持锁定；
   - 有些接口会 `code=-352`（风控校验失败）、`HTTP 412`（需要 wbi 签名），我们不做绕签名，改成降级 + 明确告知缺哪些信号；
   - 粉丝/关注比这类信号匿名接口 `x/relation/stat` 就能取，简介和认证走 `x/web-interface/card`；「最近发布时间」拿不到时按未知处理，不猜。
5. **AI 分类怎么保证不越权**：BYOK，弹窗写清发送哪些字段，可只发昵称；不填 Key 走离线规则分类。
6. **安全边界**：七条护栏（默认关闭、diff 预览、手输 UNFOLLOW、上限 50、速率 800ms、keep 白名单、审计+一键重新关注）。
7. **给不愿意装插件的人**：油猴脚本只读模式。
8. **结尾**：MIT、Issues 欢迎、README 顶部有安装图文；顺带一句 GitHub README 不能内嵌视频，所以我们把演示做成内联动图（这个坑值得单独一段，技术读者有共鸣）。

## 3. V2EX（`/share` 或 `/create`，技术向）

标题：`[开源][Chrome 插件] 把 B 站关注列表读全 + AI 语义分类 + 自然语言批量清理（护栏做满）`

正文要点（少营销，多实现细节，V2EX 只吃这套）：
- 为什么从 Python CLI 转成 MV3 插件：分发成本。之前要 clone + `pip install -e .`，转化率低到没意义；现在解压加载。
- 架构：MV3 + Side Panel 做主 UI，service worker 做抓取与写操作，`biliApi.js` 是唯一接口层；**零构建步骤**（原生 ESM，无打包器、无 node_modules），Load unpacked 即用。
- 三个真实坑（带实测码）：
  1. `x/relation/followings` 匿名返回 `-101 账号未登录`，必须在扩展里带 cookie；`x/relation/followers` 返回 `-352`；`x/space/arc/search`、`x/polymer/web-dynamic/v1/feed/space` 直接 `412`（wbi 签名）→ 所以「最近活跃」只做近似（置顶视频 `pubdate`）并标注近似，不做绕签名；
  2. 「读全」必须是硬门禁：`fetched == total` 才解锁分类，否则半截列表会让 AI 分类结果看起来很像结论；
  3. GitHub README 无法内嵌视频：实测 `<video>` 被 sanitize，mp4 链接只渲染成下载链接，所以演示用内联 GIF（≤8MB），完整片放 Pages 落地页 + B 站。
- 取关的安全设计：默认关闭 + diff 预览 + 手输 `UNFOLLOW` + 上限 50 + ≥800ms + `keep` 白名单 + 熔断断点 + 审计 CSV + 一键重新关注（`x/relation/add`）。
- 已知限制照实写：登录态失效要重登；大列表（1000+）抓取耗时长；Edge/CWS 上架还在流程里；不提供云端托管。
- 结尾：仓库地址、MIT、测试报告位置（`docs/qa-report-v2.md`）。
